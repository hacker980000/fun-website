## Scope

Stage 23 is an additive real-device/emulator evidence-baseline update. It does not change production typing, prediction, autocorrect, AI, backend, context, safety, account, subscription, training, or normal key-touch behavior. The update adds repeatable Android evidence collection and API-matrix aggregation on top of the complete Stage 22 validation chain.

## Stage 23 changes verified

- Added `stage23_ci_real_device_baseline.sh`, which first runs the complete Stage 22 chain and then performs repeated controlled baseline rounds.
- Default baseline is five rounds, configurable from 3 to 20 with `STAGE23_ROUNDS`.
- Each round records Android cold/warm `am start -W` evidence, required Stage 21 cold-start milestones, process survival, `dumpsys meminfo`, `dumpsys gfxinfo ... framestats`, and crash/ANR log evidence.
- The controlled prediction fixture remains fixed (`thank -> you`); Stage 23 does not collect or replay real user text.
- Non-account device metadata is recorded for interpretation (API, Android release, manufacturer/model, product, ABI, emulator flag, build type). ADB serial is deliberately not written to evidence.
- Added `stage23_parse_device_evidence.py` to normalize round evidence into `baseline-metrics.csv`, `baseline-summary.json`, and `baseline-summary.txt`.
- Added `stage23_merge_device_evidence.py` to build a cross-device/API matrix without assigning winners or inventing thresholds.
- GitHub Actions automatic API 36 smoke now runs Stage 23, while manual workflow runs API 26/30/36 Stage 23 compatibility baselines and uploads a merged matrix summary.
- Stage 23 keeps crash/ANR, process survival, required milestone presence, and controlled prediction behavior as hard gates.
- Stage 23 deliberately keeps latency, memory, and frame metrics evidence-only. No performance threshold is fabricated before real results exist.

## Verification boundary

This execution environment does not provide ADB or system Gradle, and the source archive does not contain the official `gradle-wrapper.jar`; it contains the pinned wrapper properties/checksum and bootstrap path. Therefore no API 26/30/36 emulator measurement or physical-device timing/memory/frame result is claimed locally.

The Stage 23 source is prepared so those measurements are generated by the configured GitHub Actions Android emulator jobs or by running `scripts/stage23_ci_real_device_baseline.sh` against an attached Android device. Emulator evidence should be treated as compatibility/regression evidence; physical-device performance data is still required before Stage 24 evidence-driven tuning.
